# TIMSUN 日本公式サイト(リブランディング版)

TIMSUN(ティムソン)タイヤの日本向けブランドサイト。
方針は「TIMSUN JAPAN リブランディング提案」(公式感×新しさ、グリーンは残して洗練)に沿う。
デザインのベンチマークはブリヂストン二輪タイヤサイト。ヒーローは本国の映像だけで見せ、文字を重ねない。

ナビゲーションは役割で3段に分ける(重複させない):

| 段 | 役割 | 位置 |
|---|---|---|
| ヘッダー(グローバルメニュー) | サイト全体の主要ページへ移動 | 最上部。画面幅いっぱいで、ロゴは左端・メニューは右端 |
| アンカーメニュー | そのページ内のセクションへ移動 | ヒーロー/ページ見出しの直下。スクロールするとヘッダーの下に固定され、見ているセクションに印 |
| フルサイズバナー(TOPのみ) | おすすめ情報のカルーセル | アンカーメニューの直下。約3.1:1、6秒で自動切替、一時停止・前後・ドット・スワイプ |

アンカーメニューは原稿の `<!--anchors: #id ラベル | ...-->` で項目を書き、本文の `<!--ANCHOR-->` の位置に入る。
製品ページはシリーズナビがページ内メニューを兼ねるため、アンカーメニューは置かない。

CJ開発ガイドに準拠(ルート相対パス、拡張子なしURL、init は `cache: 'no-cache'`)。

## TOPの構成

ヒーロー(本国映像)→ バナー → タイヤを探す(プルダウン式)→ **注目のタイヤ** → シリーズ(大きな縦長パネルの横並び)→ **ストリートハイグリップ**(上位ブランドとして紹介。薄い背景に、ロゴとブランドの言葉+最新モデルTS720 GECKOの2列、その下に全パターンのラインアップ)→ **使い方から選ぶ** → **Movies**(シネマティックな黒地に、段ごとに高さをそろえて横幅いっぱいに敷き詰める。横長は大きく、縦長は同じ高さで細く。スマホは横長1本ずつ・縦長は2本並べる。冒頭8秒・無音のプレビュー(横長は幅720px、縦長は360×640px、H.264)を `assets/video/movies/` に置き、画面に入っている間だけ再生。押すとInstagramの元のリール、またはブランドページの紹介動画を音声つきで)→ **TIMSUNを知る**(MEDULLAの「MEDULLAとは」に倣い、大きな紹介ブロック「TIMSUNとは」+ 入口カード3枚〈ヤモリの設計思想・技術と品質・取扱店〉で強弱をつける)→ **イベント**(黒い独立セクション。audi.co.jp「トピックス」に倣い、大きな写真 → 英字のイベント名 → 日付 → 説明 → 詳しく見る、を横スクロール)→ **ニュース**(別セクションの一覧)→ **タイヤの読みもの** → **適合検索・サポートへのバナー2枚**

| セクション | 中身の置き場所 |
|---|---|
| 注目のタイヤ | `data.js` の `FEATURED`(順番)・`NEW_PATTERNS`(新着)。売れ筋データがないため「人気」バッジは付けない |
| 使い方から選ぶ | `data.js` の `USECASES` |
| タイヤの読みもの | `data.js` の `ARTICLES`(FAQ・サポートの事実の範囲で書く)と `MEDIA`(メディア掲載) |


## グローバルメニューのパネル

メニューにマウスを乗せると、ヘッダーの下に画面幅いっぱいのパネルが開き、サムネイル付きで下層へ案内する(参考: sp-connect.customjapan.net)。
中身は `dev/build.py` の `MEGA`(サムネイル `tiles`・大きなバナー `banners`・「すべて見る」`all`)。スマホではパネルを出さず、メニュー一覧のみ。

## プルダウン式の車種検索

メーカー → 排気量(海外はブランド)→ 車種 → 型式(任意)を順に選び、「適合を見る」で適合タイヤ検索の結果へ移る(参考: shad-japan.com「車種から探す」)。
TOPの「車種から探す」タブと、適合タイヤ検索ページの上部に置いている。適合タイヤ検索ページでは、プルダウン → 「または、車種名・型式で探す」(候補が出るキーワード検索。検索欄はこの1つだけ) → 「または、メーカーのロゴから選ぶ」の順に並べている。部品は `assets/js/fitselect.js`、車種ツリーの組み立ては `assets/js/fittree.js`(適合検索ページと共通)。

## ページの編集と生成

ルートの `*.html` は **生成物**。直接編集しない。

1. 本文を `dev/pages/<ページ>.html` で編集する(先頭のコメントでタイトル・説明・CSS・JSを指定)
2. `python3 dev/build.py` で、共通のhead・ヘッダー・フッターを付けてルートに書き出す

ヘッダーのメニューとフッターは `dev/build.py` の中で1か所管理している。

### シリーズと型番

本国(timsun.com.cn)の9シリーズに揃え、日本で扱いのないレーシングを外し、日本独自の「ビジネス」を加えた。
型番→シリーズの対応は `data.js` の `PATTERNS`。**新しい型番が出たら `PATTERNS` に追加する**(未登録の型番は製品ページに出ない)。
グレードは商品名に「ストリートハイグリップ」を含むかで判定する。

## 適合タイヤ検索のしくみ

参考: [tire.customjapan.net](https://tire.customjapan.net/) の「車種で探す」。

1. `api-i /api/v1/init` で認証Cookieを取得(Cookieが無いと検索APIは400)
2. `api-a`(Algoliaプロキシ)で **TIMSUNのバイクタイヤ全件の適合データ** を1回取得
3. その適合データから「車両メーカー → 排気量(海外はブランド) → 車種 → 型式」を組み立てる(TIMSUNが適合する車種しか出ない)
4. 型式を選ぶと、適合する商品IDだけ商品情報(画像・価格・在庫)を取得

サイズ検索・製品一覧は全商品(`fetchCatalog`)から作る。

### TIMSUN以外を出さないための対策(二重)

- APIの検索条件に必ず `maker.id:"490"` を付ける … `cj-api.js` の `BASE_FILTER`
- 表示前にも `maker.id === "490"` 以外を除外する … `cj-api.js` の `onlyTimsun()`

### 型式キーの対応

`moto.frame.facet` のキーは車種の英字名を変換したもの(`-`→`_`、空白→`-`、`'` `:` 削除、`Γ`→`!Gamma;`、同名は `-1` `-2`)。
`fitment.js` の `norm()` で照合している。型式データの無い車種(海外車など)は車種単位で適合タイヤを表示する。

## 公開前に必要なこと

- **API の CORS 許可**: `api-a` / `api-i` は許可されたオリジンからしか呼べない。TIMSUNサイトの公開ドメインをCJ側で許可リストに追加してもらう。
- **x-site の値**: `cj-api.js` の `SITE`(暫定 `ec`)。TIMSUNサイト用の値が払い出されたら差し替える。
- **OGP**: 公開ドメイン確定後に `dev/build.py` の head に `og:url` / `og:image` / `canonical` を追加。
- **お問い合わせ**: 現在は現行サイト(timsun-japan.com/contact)のフォームへリンク。新サイトでフォームを持つなら送信先の用意が必要。
- **ニュース記事**: 一覧は新サイト、各記事は現行サイトへリンク。記事を移す場合は別途。
- **タグライン**: 「毎日を、もっと先へ。」は提案段階の案。確定したら差し替える。
- **`dev/` はアップロードしない**(原稿・生成スクリプト・開発用スナップショット)。

## ローカル確認

localhost は CORS 許可外のため、localhost では自動的に `dev/fitment-snapshot.json` を使う(本番では使われない)。

```bash
npx http-server . -p 8100 -c-1
```

→ http://localhost:8100/

スナップショットの更新: `python3 dev/refresh-snapshot.py`

**`dev/refresh-snapshot.py` と `dev/fitment-snapshot.json` は社内APIに関わるため、公開リポジトリには含めていない**(`.gitignore` で除外)。ローカルで確認する場合は社内で受け取って `dev/` に置く。ないときは localhost でも本番APIを呼びに行き、CORSで失敗する。

## 見出しの強弱

- **日本語で大きく見せる**: 伝えたい言葉がある所だけ(ページのタイトル、TIMSUNとは、ストリートハイグリップ、締めのバナー)。
- **英語だけで分かる**: 一覧の見出し(Featured Tyres / Product Series / By Riding Style / Events / News / Magazine)。小さめの英字1行+右に「一覧」リンク。日本語は読み上げ用にだけ持たせる。
- **書かない**: 中身を見れば分かる所(検索パネル、バナー、カードの並び)。

## 動画の軽さ

- ヒーロー: パソコンは `hero.mp4`(1600×900・約6.8秒・約1.9MB)、幅760px以下は `hero-sp.mp4`(1024×576・約0.9MB)を `<source media>` で出し分け。工場の場面は外している
- Movies: 1本あたり約0.3〜1.2MB、11本で約7MB。押すまで/画面に入るまで読み込まない(`preload="none"`)
- ミスターティムソンの紹介動画: 1280×720・45秒・音声つきで約6.8MB。押すまで読み込まない
- WebM(VP9)・AV1も試したが、この素材ではH.264より重くなったため使っていない

## 商品詳細ページ(`/products?p=TS689`)

ブリヂストン(二輪用タイヤ BATTLAX RACING STREET RS12 の商品詳細)の構成に倣う。上から:

1. 名前(グレードのロゴ+大きな型番)と、最安値・「サイズと価格を見る」。その下にスクロールで上に固定されるページ内メニュー
2. 大きな製品写真。型番の表記ごとの全体写真とトレッド面の写真を右のサムネイルで切り替え
3. 特長: 一行の説明と仕様(シリーズ・グレード・装着位置・構造・リム径・サイズ数)、日本公式サイトの説明文(型番の表記ごと)、製品の特長画像(オンラインストアの商品画像4枚目以降)
4. トレッドパターン: 黒地に大きな型番の文字とトレッド面の写真
5. サイズ・価格: フロント/リア/前後兼用/前後セットに分けた表。標準リム幅・許容リム幅・外径・トレッド幅・メーカー希望小売価格・オンラインストア価格は商品マスター、在庫はオンラインストアの最新
6. 適合車種: 適合タイヤ検索と同じ車種データから、メーカー別に車種を並べる(最初は24車種、残りは「すべて表示」)
7. 同じシリーズのタイヤ

`?p=TS720&i=29090884` のように商品IDを付けると、その商品を「選んだサイズ」として名前の下にまとめて見せ(寸法・価格・在庫・オンラインストアで購入)、サイズ表の行にも印を付ける。適合タイヤ検索の結果カードはこの形でリンクする(オンラインストアへ直接は飛ばさない。購入はこのページから)。


詳細ページは、商品名に型番(TS○○○)があれば必ず作られる。`data.js` の `PATTERNS` に未登録の新しい型番も、シリーズ「その他」・説明文の最初の一文で自動的に表示する(製品一覧に並べるには `PATTERNS` にシリーズと一行の説明を足す)。

## 商品マスターから商品ページを作る

製品一覧と商品詳細(`/products`、`/products?p=TS720`)は、商品マスター(CSV)から作った `assets/data/master.json` を表示している。マスターを更新したら:

```
python3 dev/make_master.py ~/Downloads/ItemList_〇〇.csv   # または dev/master/ItemList.csv に置いて引数なし
python3 dev/build.py
```

- **マスターのCSVは公開しない。** 仕入単価・仕入先・社内メモ・担当者名などを含むため、`dev/master/` は `.gitignore` で除外している。`master.json` には公開してよい項目だけを書き出す(項目の一覧は `dev/make_master.py` の冒頭)
- 対象は「Web非表示=0」のタイヤ(チューブ・販促物・訳ありは除く)
- 説明文サブは「毎日走るあなたへ、もっと安心を!」の前をシリーズ共通の文、後をパターン固有の文として分ける
- マスターの「?」になった波ダッシュ(250cc?400cc)と CO₂ は生成時に直す
- `data.js` の `PATTERNS` に無い型番は、マスターのジャンル(スクーター/ビジネス/オンロード/オフロード…)でシリーズを決め、キャッチを一行の説明にする
- 在庫だけはCJ APIの最新を重ねる(マスターに在庫は無い)
- TOPの注目のタイヤと適合タイヤ検索は、今もCJ APIの商品情報を使っている

## 共有(OGP)

- 全ページの `<head>` に canonical・OGP(og:title / description / url / image など)・X(Twitter)のカードを `dev/build.py` で入れている
- 共有画像は `assets/img/ogp.jpg`(1200×630、ヒーローの写真+ロゴ+「日本公式サイト」)
- 絶対URLは本番ドメイン `https://www.timsun-japan.com` で書き、GitHub Pages 用の書き出し(`dev/build_pages.py`)ではテスト公開のURLに置き換える。本番ドメインが違う場合は `build.py` の `ORIGIN` と `build_pages.py` の `PROD` を直す
- 商品詳細(`/products?p=…`)は画面をJavaScriptで作るため、共有時は製品一覧の内容・画像で表示される
